# 自动选点边界问题（2026-11-03）

自动选点算法保持上游 280e85e 的实现，尚未修改。以下是合成数据的实际复现，不代表每份真实实验数据都会失败。

## 当前算法如何选点

燃烧热需两个基线区间，返回 `[起点1, 终点1, 起点2, 终点2]`；溶解热需三个基线区间，返回六个索引。

程序从前后两端扩展直线拟合范围，残差超过初始噪声的 3.5 倍时，认为到达温度变化段。最小拟合长度由 `min_len = max(3, round(20 / 采样间隔中位数))` 算出，再向内让出 5 个点。溶解热还在中间找最低点，结合加热开始时间确定低温平台。

问题在于：点数不足时返回的是重复端点；时间不足时没有约束 min_len 与总点数的关系；没有温度事件时仍强行生成前后基线。最后也没有检查索引是否越界、区间是否有序、拟合点数是否足够。

## 例一：点少，但记录时间未必短

燃烧热数据有 40 点，每 10 秒一点，时间从 0 到 390 秒。温差按 `0.00002*t + 1/(1+exp(-(t-160)/8))` 生成，包含升温前后平台。

因为点数小于 50，函数不分析曲线，直接返回 `[0, 0, 39, 39]`。前区间只有第 0 点，后区间只有第 39 点；拟合直线的斜率和截距至少需要两个点，因此 curve_fit 报 TypeError。40 点即使改为每 0.5 秒采样也得到同样结果。

溶解热少于 60 点时也存在同类分支，40 点返回 `[0, 0, 0, 0, 39, 39]`。

实际场景：提前停止采集，或把完整实验降采样后再导入。后一种场景可能有足够物理信息，因此不能简单把所有少于 50/60 点的数据都当作无效实验。

## 例二：点数够，但总时间不够

100 点，每 0.1 秒一点，总跨度 9.9 秒，温差为 `0.001*t`。

点数通过了 50/60 点门槛，但 20 秒基线对应 200 个点，超过了总共 100 个点。

- 燃烧热返回 `[0, 200, -101, 99]`，有效索引本应为 0 到 99。
- 溶解热在中间区间取最低点时，区间为空，报 `ValueError: attempt to get argmin of an empty sequence`。

实际场景：导入高频采样的短片段。这不等于本软件默认每 0.1 秒采集；默认 GUI 调度约 0.5 秒，外加读取和绘图耗时。模拟器发送频率与 GUI 记录频率也不同。

这种片段本身不足以提供完整实验的几个基线，合理处理通常是提示继续采集或换完整数据，而不是强行产出热量。

## 例三：记录较长，但没有发生实验温变

100 点，每秒一点，总跨度 99 秒，温差为 `0.001*t`，即只缓慢线性漂移 0.099 K，没有点火、溶解或加热事件。

因为整段都是直线，前后扩展始终找不到残差超限的位置。前区间扩展至尾部，后区间又被最小长度规则挤到前区间里面。

- 燃烧热返回 `[0, 94, 79, 99]`：前基线覆盖 0–94 秒，后基线覆盖 79–99 秒，两者重叠。
- 溶解热在前终点 94 与后起点 79 之间取最低点，得到空区间并报同样的 ValueError。

实际场景：误点开始后没有进行实验，或只导出了实验开始前的稳定段。应该明确提示没有找到足够平台，不能将这种数据强制计算为有效实验结果。

## 正常曲线对照

480 点、每秒一点，温差 `0.00002*t + 1/(1+exp(-(t-120)/8))`，燃烧热返回 `[0, 40, 198, 479]`，区间有序且不越界。现有溶解热选点测试，以及两种模式的完整 GUI 计算与导出测试也通过。

这说明已确认的是边界处理缺陷，不足以断言正常实验数据的选点都不可靠；合成曲线通过也不等于已验证真实仪器的精度。

## 可选择的修改范围

建议先做输入和输出保护：检测时长、索引顺序、每段点数和区间间隔；找不到合理平台时保留原始曲线并提示手动选点或继续采集。正常长曲线的自动选点策略可以保持原样。

稀疏但完整的记录需要单独决定是否允许自动选点：可以用时间跨度与每段最小点数共同判定，代替固定 50/60 点门槛；也可以允许导入后只提供手动选点。这个决定与不足 10 秒的片段、没有实验事件的数据应如何拒绝是两件事。

另外，当前 wrapper 没有使用传入的 time_lower_limit、time_upper_limit 和 std_limit，实际调用内部默认 20 秒及残差倍数。单改 main.py 中旧的 30/40 秒配置不会解决上述问题。
