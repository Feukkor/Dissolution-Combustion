# 自动选点边界问题（2026-11-03）

自动选点算法沿用上游 280e85e 的实现，目前尚未修改。下面是合成数据上的实际复现，不代表每一份真实实验数据都会失败。

## 当前算法如何选点

燃烧热需要两个基线区间，函数返回 `[起点1, 终点1, 起点2, 终点2]`；溶解热需要三个基线区间，返回六个索引。

程序从前后两端逐渐扩展直线拟合的范围，当残差超过初始噪声的 3.5 倍时，就认为已经到达温度变化段。最小拟合长度按 `min_len = max(3, round(20 / 采样间隔中位数))` 计算，然后向内让出 5 个点。溶解热还会在中间找最低点，结合加热开始时间确定低温平台。

问题在于：点数不足时返回的是重复端点；时间不足时没有约束 `min_len` 与总点数的关系；没有温度事件时仍然强行生成前后基线。最后也没有检查索引是否越界、区间是否有序、拟合点数是否足够。

## 例一：点少，但记录时间未必短

燃烧热数据 40 点，每 10 秒一点，时间从 0 到 390 秒。温差按 `0.00002*t + 1/(1+exp(-(t-160)/8))` 生成，包含升温前后的平台。

因为点数小于 50，函数不分析曲线，直接返回 `[0, 0, 39, 39]`。前区间只有第 0 点，后区间只有第 39 点；拟合直线的斜率和截距至少需要两个点，因此 `curve_fit` 报 TypeError。40 点即使改成每 0.5 秒采样，结果也一样。

溶解热在少于 60 点时也存在同类分支，40 点会返回 `[0, 0, 0, 0, 39, 39]`。

实际场景：提前停止了采集，或者把完整实验降采样后再导入。后一种情况可能仍然含有足够的物理信息，所以不能简单地把所有少于 50/60 点的数据都当作无效实验。

## 例二：点数够，但总时间不够

100 点，每 0.1 秒一点，总跨度 9.9 秒，温差为 `0.001*t`。

点数通过了 50/60 点的门槛，但 20 秒的基线对应 200 个点，已经超过了总共的 100 个点。

- 燃烧热返回 `[0, 200, -101, 99]`，有效索引本应为 0 到 99。
- 溶解热在中间区间取最低点时，区间为空，报 `ValueError: attempt to get argmin of an empty sequence`。

实际场景：导入高频采样的短片段。这不代表本软件默认每 0.1 秒采集一次；默认的 GUI 调度约 0.5 秒，另外还有读取和绘图的耗时。模拟器的发送频率与 GUI 的记录频率也不相同。

这种片段本身就提供不了完整实验所需的几个基线，比较合理的处理是提示继续采集或者换一份完整的数据，而不是硬算出热量。

## 例三：记录较长，但没有发生实验温变

100 点，每秒一点，总跨度 99 秒，温差为 `0.001*t`，也就是只缓慢线性漂移了 0.099 K，没有点火、溶解或加热事件。

因为整段都是直线，前后扩展始终找不到残差超限的位置。前区间一直扩展到尾部，后区间又被最小长度规则挤进了前区间里面。

- 燃烧热返回 `[0, 94, 79, 99]`：前基线覆盖 0–94 秒，后基线覆盖 79–99 秒，两者重叠。
- 溶解热在前终点 94 与后起点 79 之间取最低点，得到空区间并报同样的 ValueError。

实际场景：误点了开始记录但没有做实验，或者只导出了实验开始前的稳定段。这种情况下应该明确提示没有找到足够的平台，不能把这类数据强行算成有效结果。

## 正常曲线的对照

480 点、每秒一点，温差 `0.00002*t + 1/(1+exp(-(t-120)/8))`，燃烧热返回 `[0, 40, 198, 479]`，区间有序且不越界。现有的溶解热选点测试，以及两种模式的完整 GUI 计算与导出测试也都通过。

这说明目前确认的只是边界处理上的缺陷，不足以断言正常实验数据的选点都不可靠；合成曲线能通过，同样不等于验证了真实仪器的精度。

## 可以修改的范围

建议先做输入和输出保护：检查时长、索引顺序、每段点数和区间间隔；找不到合理平台时保留原始曲线，并提示手动选点或继续采集。正常长曲线的自动选点策略可以保持原样。

稀疏但完整的记录要不要允许自动选点，需要单独决定：可以用时间跨度与每段最小点数共同判定，代替固定的 50/60 点门槛；也可以允许导入后只提供手动选点。这个决定与“不足 10 秒的片段、没有实验事件的数据如何拒绝”是两件不同的事。

另外，当前这层 wrapper 没有使用传入的 `time_lower_limit`、`time_upper_limit` 和 `std_limit`，实际调用的是内部的默认值（20 秒及相应的残差倍数）。只改 `main.py` 里旧的 30/40 秒配置并不能解决这些问题。

## 复现命令

